# 项目 / 工作区分区与归档（2026-10-11）

基线：`e58d636`，备份分支 `backup/project-archive-20261011`。远端与本地同基线、工作区干净后开始。用户追加移动端 agent team 任务，与本项独占文件分工并行。

## 已实现

- 项目面板上半区：项目、方向和论文工作区列表；下半区：所选项目的工作区设置。上下区域独立滚动，用分隔线区分，显示当前工作区名称，目录位置设置直接放在下面。项目记忆/运行默认折叠，避免抢占设置空间。
- 项目/整个方向提供更多操作菜单。活动项目先归档，归档页中恢复或移除；归档方向批量处理该方向的活动项目。移除方向批量移除归档成员。
- 对话列表与对话标题菜单统一先归档；对话列表顶部归档按钮中恢复或永久删除。通用对话同样支持。
- 项目归档同时归档所属对话，恢复时只恢复因该项目归档的对话；原先单独归档的对话保持归档。归档对话从普通列表、收件箱计数/列表排除。
- 项目移除保留元数据墓碑，保留论文库、工作区文件和 Git 历史；对话仍留在对话归档，可单独恢复/删除。元数据墓碑避免打开原论文时自动创建另一个工作区。移除本身不支持恢复。
- 后端拒绝归档运行中、待交互中的对话/项目、运行中的经典 agent 任务或正在移动的工作区。归档对话不能发消息，归档项目不能新建会话。恢复项目后可以继续。
- 所选项目归档后清空选择；重新刷新时也会移除失效选择。下方详情按项目 id 重置，避免旧项目设置异步返回覆盖当前内容。
- 实测发现 Windows 后台 Git 设置读取项目 JSON 时会与原子替换竞争；项目读取现在使用同一把 RLock。

## 接口

- `GET /api/agent/projects?archived=true`、`GET /api/sessions?archived=true`：归档列表。默认只列活动项。
- `POST /api/agent/projects/{id}/lifecycle`：`{"action":"archive|restore|remove"}`。
- `POST /api/agent/categories/lifecycle`：同 action 加 `name`，批量处理研究方向。
- `PATCH /api/sessions/{id}`：`{"archived":true|false}`；现有 DELETE 保持兼容，UI 仅在归档页提供永久删除。
- 老记录没有 `archived` 字段按活动处理，无须迁移数据库。
