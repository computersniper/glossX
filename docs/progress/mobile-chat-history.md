# 扫码连接后的会话历史与紧凑额度入口

日期：2026-10-11。起点 `4b8c9f7`，修改前备份分支 `backup/mobile-chat-quota-20261011`。

用户反馈：手机扫码连接电脑后无法显示对应 agent 会话记录，同时希望有不占据主页的额度显示。

## 发现与修改

- `sessionStore.watch()` 原先只订阅 SSE；`sessionsApi.get()` 虽已存在，打开会话时没有读取历史。代理缓冲/阻断事件流时，历史永远没有载入。代码确认了这个故障路径；尚未取得用户真实手机与 Cloudflare 的网络日志，不能断言其实际网络阻断原因。
- 打开/恢复会话时并行用普通 GET 获取完整历史，SSE 继续接收实时事件。HTTP 请求期间有更新的 SSE 事件到达，就舍弃旧快照，避免覆盖新消息。
- 收到事件后记录时间；超过 20 秒没有事件，每 10 秒检查并补取快照；流出错立即补取。请求串行，取消订阅后丢弃迟到响应并清理轮询。正常空闲会话也会周期同步，以覆盖“连接打开但代理不转发事件”的情形。
- 首次历史读取失败会显示错误，而不是永久加载；后续成功读取或 SSE 恢复清除该历史加载错误。
- 手机和 iPad 顶部增加小型额度按钮：简略显示第一项限额的**已用百分比**，点击展开原有完整额度弹层；移动端底部不重复显示。以当前会话的 provider 优先，没有显式 provider 时采用默认值。API 提供商没有可读取账号额度时，不伪造余额。

## 验证与接续

- TypeScript、Vite 构建、前端 29 个现有测试通过。
- `scripts/dev/ui_mobile_chat_history.cjs` 使用隔离的真实后端和 Edge 手机/iPad 视口；通过真实 token 换 HttpOnly cookie，模拟非本地访问。会话生成使用隔离假 provider，绝不执行真实 Codex/Claude。
- 额度使用固定响应，不声称真实账号额度验证。回归覆盖正常/阻断 SSE 两种模式、用户消息、agent 回复、两会话切换、普通请求加载、阻断后新消息轮询补取与额度弹层。
- 未实测用户手机、Safari/WebKit、真实 Cloudflare 网络；未构建/安装 exe 和原生移动包，未运行付费模型调用；由用户检查 workflow 成品。更新电脑端程序后，手机重新打开电脑提供的新前端即可得到修复。
